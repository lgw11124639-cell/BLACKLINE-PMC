# BLACKLINE PMC

자율 경영·작전 관찰 시뮬레이션. GitHub Pages에 `main` 루트가 배포됩니다.

## 개발 및 검사

빌드나 패키지 설치 없이 실행합니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
node --test tests/*.test.cjs
```

모든 JavaScript 파일과 `index.html`의 인라인 스크립트는 배포 전 구문 검사합니다. 브라우저 검증에는 Python Playwright와 Chromium이 필요합니다. `tests/browser-contracts.py`는 현재 서버(8000)와 v2026.11.09.28 서버(8001)를 대상으로 이전 저장 복구, 진행 중 작전 재개, 중복 정산 방지, 모바일 화면, 백업 복구를 검사합니다. 이전 버전은 별도 임시 디렉터리에 `git archive bb683e55fa9cf142d6134baa219a68683d519757`으로 추출하여 8001에서 정적 제공할 수 있습니다. 테스트는 별도 브라우저 컨텍스트의 가상 저장 데이터만 사용합니다.

## v2026.11.09.29: 지역 정세와 계약시장

`contract-world.js`는 기존 18개 작전 템플릿을 유지하면서 가상 지역 3곳과 고객별 신뢰·가용 예산·수요를 저장합니다. 치안·분쟁·정치 불안·경제가 일별로 서로 영향을 주며, 분쟁이 높은 지역에서 발생한 시설 위협 사건이 긴급 의뢰의 원인이 됩니다. 신규 계약 위험도와 보수는 해당 지역 및 고객 관계에 따라 조정됩니다. 회사 평판과 누적 성공 전문 분야도 의뢰 접근과 우선순위에 반영됩니다.

신규 계약은 템플릿과 별도의 숫자 ID를 가집니다. 제안 때 고객 예산을 예약하고, 만료·작전 보류 시 반환하며, 종료 때 실제 보수와 차액을 정산합니다. 수주한 계약은 사본을 작전에 보관하므로 제안 마감과 관계없이 진행됩니다. 작전 성공·실패 및 적대 인원 이탈이 지역 정세와 고객 신뢰에 반영되고, 성공한 고객은 신뢰 조건을 충족하면 원래 계약을 명시한 후속 의뢰를 제안합니다.

기존 `blackline_pmc_v1` 및 `blackline_pmc_v1_backup` 키를 유지합니다. 기존 계약과 진행 중 작전은 데이터를 보존하며 이전 기록에 정산을 소급 적용하지 않습니다. 새로고침으로 계약을 재생성하지 않으며, 빠른 날짜 진행 중복 입력과 동일 작전의 재정산을 차단합니다. 사건은 30개, 미수주 제안은 최대 7개로 제한합니다.

현재 후속 경비는 단일 작전입니다. 여러 날의 장기 계약 집행, 경쟁 PMC 입찰·협상, 실제 대원 위치 기반 전투와 탄약·부상의 완전한 연계는 아직 구현하지 않았습니다. 3D는 기존의 추상 관찰 화면을 유지하며 Three.js CDN과 WebGL을 사용할 수 없으면 기존 대체 화면을 사용합니다. iPhone 실기기 검증은 별도로 필요합니다.

릴리스 때 `version.json`, `update-check.js`의 현재 버전 및 `index.html`의 변경된 스크립트 캐시 버전을 함께 갱신합니다.

## v2026.11.09.30: Executive UI

밝은 아이보리·화이트 배경, 블루 포인트와 문서 중심 레이아웃을 적용했습니다. PC는 좌측 사이드바, 모바일은 하단 메뉴를 사용합니다. 시작/저장 관리, 인사기록, 군수 재고, 계약시장, 보고서 및 관찰/다시보기 화면을 같은 테마로 통일했습니다. `executive.css`와 `executive-ui.js`는 표현만 담당하며 기존 시뮬레이션·저장 키를 유지합니다. 추가 글꼴이나 UI 라이브러리를 내려받지 않습니다.

현재 앱 서버를 8000에서 실행한 뒤 `python3 tests/browser-ui.py`로 320/390/768/1440px 화면의 메뉴, 인사기록 탭, 보고서 검색·필터, 날짜 진행, 백업 내보내기 및 저장 복원을 확인할 수 있습니다. Playwright와 Chromium이 필요합니다. iPhone 실기기 검증을 대신하지는 않습니다.

## v2026.11.09.34: 실시간 현장 전용 관찰

**관찰** 메뉴는 실제 진행 중인 작전만 표시합니다. 대기 중에는 출동 대기 지도가 표시되며 시연·기록 선택·재생 배속·시간 이동은 나오지 않습니다. 완료 작전의 다시보기는 본부의 결과 보고서에서 별도 기록 창으로 엽니다.

정상 작전은 현실시간 약 15분입니다. 실제 1초에 작전도 1초 진행하며 접근·수색·과업·복귀를 거쳐 900초에 종료합니다. 경로 지연 시 최대 18분까지 이어질 수 있고, 전멸·조기 철수는 빨리 끝날 수 있습니다. 탭을 숨기거나 앱을 닫거나 시간을 일시정지하면 진행도 멈추며, 오프라인 결과를 임의 생성하지 않습니다. 실시간 작전 배속은 제공하지 않습니다.

- `field-tactics.js`는 신규 작전의 좌표·건물 차폐·인지 시간·각 대원의 관측 기억을 처리합니다. 아군은 알려진 의뢰 구역으로 접근한 뒤 수색하며, 보이지 않는 적의 실제 좌표를 따라가지 않습니다. 총성은 방향 단서일 뿐 정확한 적 위치를 알려주지 않습니다.
- 실제로 관측한 상대만 지도에 나타납니다. 시야에서 사라지면 마지막 관측 위치를 잠시 남긴 뒤 60초에 폐기합니다. 위치가 바뀌어도 미관측 적의 정확한 위치를 추적하지 않습니다. 타격 지원도 최근 확인된 표적과 안전거리 조건을 만족해야 집행합니다.
- `images/operators/pmc-directions.webp`는 입체 렌더 대원의 8방향 이미지입니다. 지도 위에서 이동·조준 방향에 맞춰 그리며 살아 있는 대원을 단순 도형 대신 이미지로 표시합니다. 실제 3D 메시/스켈레탈 엔진은 아닙니다. 지형은 광역·시가지·산악·산업지구 4종이며, 각 지도에 별도 충돌 영역·출동 경로·전술 위치를 둡니다. 광역 지도 좌표 면적은 산업지구의 약 10배입니다.
- `field-roles.js`에서 현장지휘관이 주특기에 따라 임무를 배정합니다. 저격수는 후방 진지·옥상에서 엄호하고, 정찰병은 고지를 확인한 뒤 전진 수색에 합류하며, 의무병은 엄호 아래 실제 부상자에게 접근해 의료품을 사용합니다. 지원 대원의 제압 사격은 상대의 명중률과 사격 간격에 영향을 줍니다. 고도는 관측 범위와 차폐 판정에 반영됩니다.
- 현장 작전 중 회사 시계도 현실시간 1:1로 고정합니다. 현장 작전이 없는 동안에는 회사 일정이 압축 진행되고 일정 배속을 선택할 수 있어 기존 회복·계약 주기를 유지합니다.
- ASTER, KESTREL, MERIDIAN은 관계가 저장되는 가상 PMC입니다. 중립 조우 또는 적대 접촉이 가능하며 각자 관측한 정보에 따라 움직입니다. 세계 전역의 독자 계약·경제까지 운영하는 단계는 아닙니다.
- 탄약 예약·반환, 실제 교전 피해와 개인 실적·정산 및 기존 저장 키를 유지합니다. 미완료 구형 좌표 작전은 인원·좌표·체력·잔탄·RNG를 보존하며 새 관측/시간 체계로 이관합니다. 이미 끝난 기록은 다시 계산하지 않습니다.
- 기록 창은 저장한 프레임·무전·관측 정보만 읽으며 정산을 재실행하지 않습니다. 좌표가 없는 이전 기록은 원래 무전/추상 3D 화면도 유지합니다.

```sh

python3 tests/browser-save-import.py
python3 tests/browser-speed.py

```

8000에서 현재 정적 서버를 실행하고 Chromium/Playwright를 사용합니다. `browser-observation.py`는 제어된 브라우저 시계로 899초/900초 경계와 LIVE/기록 분리를 검사합니다. `browser-realtime.py`는 실제 대기 시간과 작전 시간의 1:1 비율을 측정합니다. 테스트는 별도 브라우저 저장소를 사용합니다. 이전 버전 호환성 검사는 8001에 v28 정적 서버를 준비한 뒤 `python3 tests/browser-contracts.py`로 실행합니다.
