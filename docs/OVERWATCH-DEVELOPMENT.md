# BLACKLINE: OVERWATCH 전환 계획

범위: 사용자 개발 지시서의 1단계. 이 문서는 전체 게임 구현 완료를 의미하지 않는다.

## 분석 기준

최종 기준 커밋 `c5704a8` (원격 main, v2026.11.10.02). 초기 로컬 `470e338`에서 시작했으나 원격 100개 추가 커밋을 확인한 뒤 최신 기준으로 재배치했다. 추가된 17개 파일의 633행 삽입/74행 삭제를 그대로 보존한다. 정적 HTML/JavaScript 프로젝트이며 빌드 도구나 서버 데이터베이스가 없다. 진입점 `index.html`은 약 62KB의 UI·초기 상태·저장 코드와 다수의 전역 스크립트를 실행한다. 최신 변경에는 의료후송 잔여 대기 정리, 지상 복귀와 헬기 도착 조건 분리, 복귀 정체 복구, 비동기 저장 보강, 60~96명 적 중대·지원전력·접촉 확률 변경과 UI 보정이 포함된다. 적 중대의 전체 아군 위치 참조와 기존 대규모 전력 정책은 OVERWATCH의 제한 정보·6명 출격 규칙과 맞지 않으므로 그대로 이식하지 않는다. 기존 상태는 `blackline_pmc_v1`, `blackline_pmc_v1_backup`에 저장한다. `save-codec.js`는 기존 JSON 및 BLZ1 압축 저장을 모두 읽는다. `save-scheduler.js`/`save-worker.js`는 기존 키에 직접 기록하므로 새 앱에서는 실행하지 않는다.

## 새 경계

- `overwatch/core.js`: DOM 없는 상태 스키마·제약·유효성 검사. 최대 10명, 출격 2~6명, ALPHA/BRAVO/CHARLIE 각 관측수+저격수. 시계는 향후 활동/실제 시뮬레이션 tick으로만 전진.
- `overwatch/storage.js`: 새 주 저장/백업, 복원·가져오기·내보내기·충돌 감지. 기존 PMC 키는 읽기 전용.
- `overwatch/app.js`와 `overwatch/app.css`: 본부·인원·작전·장비·기록·저장 관리. 미구현 단계는 명시하고 실행 버튼을 제공하지 않는다.
- 후속: command/event queue, observer AI, world truth, HQ knowledge, transport FSM을 독립 모듈로 추가. 2D/3D는 HQ에 전달된 동일 frame을 읽는다. 시각화가 적 실제 좌표를 따로 조회하면 안 된다.

## 단계 및 완료 기준

1. **본부/저장**: 새 진입점, 독립 상태, 기존 원본 보존, 백업/가져오기/손상 복구, PC/모바일 검사. 구형 게임은 `legacy-pmc.html` 및 Git 이력으로 보존하며 새 앱에서 자동 실행하지 않는다.
2. **인원/편제**: 모집·계약·훈련·의료와 10명 상한, 주특기 1개/부특기 0~2개, 최대 3개 2인조, 사망 영구 보존. 실제 입출금/편성 검사.
3. **AI/무전/정보**: 명령 수신→복창→관측수 판단→내부 지시→행동→실제 사건 보고. 통신 단절/오래된 정보/관측수 행동 불능 대행 검사.
4. **전장**: 1/2/4배속·일시정지·긴급 정지, 실제 2~6개 개체와 독립 적 AI, 지형/기상, 동일 상태 2D/3D 및 성능 검사.
5. **계약/지원**: 기관별 목표·제약·제공 지원. 수송 출발/이동/착륙/하차/철수/탑승, 지원 없는 임의 출동 금지. 목표 완료와 철수/정산 분리.
6. **통합**: 실제 사격만 탄약 소비, 재장전·성장·해금, 중복 정산 방지, 진행 중 저장/복구·장기/모바일 검사.

## 저장 전환

기존 36명 편제나 진행 중 24명 작전을 새 10명/6명 제한에 맞춰 자르지 않는다. 기존 두 키의 원본 바이트는 수정/삭제하지 않는다. 새 진행은 `blackline_overwatch_v1`/`blackline_overwatch_v1_backup`에 별도로 저장한다. 기존 명부·작전·보고는 보관함에서 요약/원본 다운로드할 수 있다. 새 데이터를 덮어쓰는 가져오기/초기화는 사전 보관본을 확보하고 실패하면 이전 값으로 복구한다. 현재 단계가 이해할 수 없는 스키마는 거부하고 원본을 보존한다.

주 저장 손상 시 백업을 제시하며 자동 덮어쓰지 않는다. 둘 다 손상되면 저장 동작을 잠그고 원본 다운로드/복구만 허용한다. 저장 실패 시 메모리 상태도 성공으로 전진시키지 않는다. 다른 탭의 새 revision을 덮어쓰지 않는다.

## 2단계 구현 범위와 정책

대원 모집·계약·편성·본부 활동을 실제 저장 상태에 연결한다. 신규/1단계 저장은 schema 2로 전환하며 변환 전 주 저장과 백업을 별도 보관한다. 1단계 저장의 ID·설정·기록·명부는 유지한다. 초기 운영자금 1억원은 캠페인당 한 번만 장부에 기록한다.

- 주특기 관측수/저격수, 부특기 0~2개. 신입·경력·베테랑·전문가 후보는 경력/능력/일급을 공개하고, 30/90일 기간 급여를 선지급한다. 계약금 중복 지급·예산 초과·정원 초과를 거부한다.
- 현직 10명과 전사/퇴사/은퇴 명부를 분리한다. 사망/부상은 임의 발생시키지 않는다. 실제 사건을 인수하는 검증/중복 방지 핸들러와 의료 상태를 구현하며 현재 UI에서 전사·총상을 만들어내는 버튼은 제공하지 않는다.
- ALPHA/BRAVO/CHARLIE에 관측수 1명+저격수 1명. 중복/부상/계약 만료/훈련 중 인원 편성 금지. 조 단위 편성만 지원하며 아직 출격이나 AI 명령 기능은 아니다.
- 본부 활동은 개인 훈련/휴식/외부 협력 진료/재활/2인 공동 훈련. 활동을 배정한 뒤 다음 활동 완료까지 시간을 진행한다. 계약 시간과 모든 동시 활동이 함께 전진하고, 재접속/실제 벽시계 경과만으로 진행시키지 않는다.
- 활동 비용은 착수 때만 지출한다. 종료 사건과 능력/피로/스트레스/치료/팀워크 변화는 실제 활동 경과에 따라 한 번만 적용한다. 진행 중 저장을 복구해도 기한을 다시 계산하지 않는다.
- 기존 상처와 후유증은 보존하고, 진료 종료까지 부상 인원의 편성을 막는다. 중상 후유증은 실제 부위 기록에서만 산출한다. 출처가 없는 이전 상처는 부위를 지어내지 않고 미상 기록으로 보존한다.
- 지휘 AI·전투·탄약·3D·기관 계약 수송은 후속 단계다. 부특기 데이터의 AI 행동 연결도 3단계에서 구현한다.

### 실제 구현과 경계

- `overwatch/geometry.js`: 기존 `field-simulation.js`의 격자 경로/모서리 차단/높이 시선 알고리즘을 독립 순수 모듈로 분리·적응했다. 구형 전역 타이머/전장/렌더러는 로드하지 않는다. 고정된 능선 지휘 훈련장이며 실제 작전 지도 생성기가 아니다.
- `overwatch/command.js`: 본부 → 관측수 수신/복창 → 능력·경력·성격에 따른 판단 지연 → 조 내부 지시 → 서로 다른 세부 위치/경로 이동 → 실제 완료 보고. 이동·관측·위치 유지·집결·교전 규칙·상황 보고 명령을 지원한다. 훈련에서는 교전 허가도 실탄 발사로 연결하지 않는다.
- 훈련에 실제 편성 대원 2~6개 개체가 존재한다. 관측수의 세부 위치 선택은 고도·시선·다른 조의 예약 위치를 사용하며 미발견 표적 좌표를 참조하지 않는다. 현장 간격 유지와 이미 도착한 조원 우회가 실제 경로에 반영된다. 경로가 실제 막히면 수행 불가 보고를 보낸다.
- 표적 훈련 인원은 독립 경로를 이동한다. 조 내부 관측은 거리·방향·건물·고도·관측 역량에 의존하며 불확실한 최초 관측과 식별 신뢰도를 구분한다. 현재는 통제된 훈련 인원 식별이며 적대/민간 판단과 실탄 교전 AI가 아니다.
- 통신·정찰 부특기와 개인 판단/팀워크·두 사람의 관계가 전달 지연·관측·내부 지시에 반영된다. 응급처치·실제 드론 전개는 아직 연결하지 않는다.
- 관측수 행동 불능은 검증 가능한 훈련 판정 사건을 입력할 때만 발생한다. 저격수 대행·긴급 보고·본부 수신 후 자동 정지 경로를 구현했다. UI에 임의 부상/행동 불능 생성 버튼은 없다. 실제 전투 부상·의무후송과의 연결은 후속 단계다.

### 제한 정보와 무전

`world`(실제 위치), 조별 `contacts`(현장 관측), `knowledge`(본부가 수신한 정보)를 분리한다. `command-view.js`는 `frame()`이 반환한 본부 투영만 사용하고 숨겨진 개체/경로/현장 상태를 직접 렌더링하지 않는다. 위치와 명령 완료·교전 규칙도 실제 보고가 전달되기 전에는 본부에 갱신하지 않는다.

무전에는 발신/수신 이름·역할·호출부호, 본부/조 내부 구분, 발생/전달 시각, 지연·전달 상태와 근거 사건 ID가 포함된다. 통신 음영 중에는 명령과 보고가 대기하며 조 내부 교신도 본부에 자동 공개하지 않는다. 복구 후 오래된 보고가 최신 위치를 덮어쓰지 않는다. 마지막 확인 위치는 실제 표적의 이후 위치를 조회하지 않고 시간에 따라 신뢰도가 감소한다.

### 시간·저장·기록

3단계는 실제 계약 출격에 앞선 **수동 시간 진행 지휘 훈련장**이다. 10/30/120초를 진행하면 내부에서는 1초씩 상태·통신·경로를 계산한다. 현실 시간/오프라인 자동 진행, 실시간 배속 루프·3D·수송·실탄 교전은 4~5단계다. 훈련 시간은 본부 시계/계약과 함께 흐르지만 부상·탄약 소모·보수를 임의 생성하지 않는다. 다른 본부 활동이 실행 중이면 시작하지 않고 훈련 중 본부 활동 변경을 막는다.

schema 3 전환은 이전 주 저장·백업의 정확한 원본을 `blackline_overwatch_v1_before_migration_v3`에 보관한다. schema 2→3에서는 자금을 다시 지급하지 않는다. 1/2단계 가져오기·복구도 최신 형식으로 변환하며 손상/저장 용량 실패 시 되돌린다. 진행 중인 AI 판단 시각·명령 큐·지연 무전·경로·국지 관측·본부 수신 상태를 저장해 동일한 다음 상태를 재개한다. 훈련 종료의 본부 수신 기록은 `commandArchive`에 별도 보관하고 다음 훈련으로 덮어쓰지 않는다.
